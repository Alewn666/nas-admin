## 2026-10-18 第三十六轮：CPU 口径修复 + 自动刷新 + CPU/内存走势图

### 结论
1. **页面 CPU 99% 是口径 bug，不是真忙**：`/proc/stat` 取「前 4 项」当总时长、只把 `idle` 当空闲 →
   `iowait`/`steal` 被算成忙；NAS 正在大量用 swap（换页时 iowait 高）→ 页面常显 97~99%，
   同一刻 top 只有 16.7%、vmstat 20%。修法：`busy = total - idle - iowait`（steal 不算忙），
   窗口 0.4s → 1.0s。改后同刻三法对照：新算法 **7.9%** / top 16.7% / vmstat 20%；
   真机页面 3.5~13.9%（能看出核间差异）。
2. **自动刷新**：总览 3/5/10/30s、容器 5/10/30s；只刷当前可见页签；页面在后台、口令遮罩打开、
   正在文本框输入、上次请求未返回 → 跳过；`localStorage` 记住开关与间隔。
3. **CPU/内存走势图**：后端 `_HIST` 环形采样（默认 5s 一点、720 点 = 60 分钟，公式与 `_cpu_pct`
   同口径）；`GET /api/charts?minutes=` 返回窗口内点。前端 canvas 手绘（**零 CDN**），双图 +
   5/15/30/60 分钟切换，随总览自动刷新一起更新；「资源占用」模式（docker stats 约 2s）禁用自动刷新。

### 证据
- `test_admin.py` **81/0**（新增 9 条：字段齐全 / 首点不造假 0% / 第二点落库 / 范围过滤 /
  非法参数回退 / 未登录 401）
- `ui_admin.py` **45/0**（新增：开关默认关、3 秒真在请求、关掉真停、切页停、偏好记忆、
  资源占用禁用、两张画布非空、范围切换重新拉取、自动刷新带动图表刷新、零 JS 报错、三视口不溢出）
- 真机 `/api/charts?minutes=15` 采到 4 点（CPU 12~28%、内存 1095~1115 / 1954 MB、swap 871~873 MB）；
  浏览器截图桌面 1280×1000 / 手机 390×844：图表均已绘制、无 JS 报错。

### 踩坑
1. **自动刷新被 select 焦点误伤**：`typing()` 把 `select` 算成「正在输入」，`select_option` 后焦点
   留在下拉框 → 自动刷新 0 次。修法：只让 text/password/textarea/contenteditable 让路。
2. **`stopAuto()` 重置整个状态对象**：`AUTO[k] = {…, mode:false}` 把刚设的 `mode` 冲掉 →
   「资源占用模式禁用自动刷新」永远失效。修法：只清 timer/inflight，保留 mode。
3. **测试自伤（Playwright）**：`pg.evaluate("… window.fetch = function(u){…};")` 这种**以函数赋值结尾**
   的字符串表达式，Playwright 会把返回值当函数、用 `null` 调一次 → `fetch(null)` → `404 /null`。
   修法：包 IIFE。诊断靠 `add_init_script` 探针抓 stack，行号直接指到测试自己。
4. **采样器懒启动**：首次请求才启动、首点只记参照 → 页面打开约 10 秒后才出图（UI 已提示「采样中」）。
   验收脚本别先 sleep 再请求，否则「刚启动就查」永远 0 点。
5. **IPv6 把 IP 卡片撑高**：手机上一屏只看到 IP，图表被挤到第二屏 → 只显示 IPv4，IPv6 记数量。

### 未做 / 不修的理由
- 图表**没有悬停 tooltip**：现值/峰值/时间轴已够用，移动端没有 hover，先不加。
- 采样历史**不落盘**：重启清零；要长期趋势应该走 `nas_metrics` 那套采集，不该让管理面板背数据库。
- 窗口上限 60 分钟（720 点）：够看短时抖动；更长周期交给历史库。

## 2026-10-18 第三十七轮：记住登录（「每次打开都要输口令」）

### 结论
用户反馈每次打开都要输口令。查出 **三个叠加原因**，全修：
1. **cookie 是会话级**：Flask 默认 `session.permanent=False` → 没有 Expires，关浏览器就丢。
   修法：登录时 `session.permanent=True` + `PERMANENT_SESSION_LIFETIME=30 天`
   （环境变量 `NAS_ADMIN_SESSION_DAYS` 可调）。
2. **SECRET_KEY 每次容器启动都随机**（`NAS_ADMIN_SECRET` 没配时随机生成）→ 重建容器后
   所有签名 cookie 立即作废。修法：deploy.sh 首次生成 env 时写入 `NAS_ADMIN_SECRET`，
   老 env 自动补一行；值固定后重启/重建都不掉。
3. **服务端会话表 `_SESS` 只在内存**：每次部署/重启清空 → 即使 cookie 有效也被踢。
   修法：`sessions.json` 原子落盘（600，只存 jti/ip/ts，不含口令），启动时读回；
   登出同步写盘，所以「吊销」也跨重启有效。

### 证据
- `test_admin.py` **91/0**（新增 10 条：有效期 ≥30 天、Set-Cookie 带 Expires、HttpOnly、
  sessions.json 存在且 600、文件含票不含口令、**重新加载模块后旧 cookie 仍 200**、
  登出后再加载模块旧票 401）
- `ui_admin.py` **46/0**（新增：浏览器里 `session` cookie 的 `expires > 0`）
- 真机：登录返回 `Expires=...`、`_permanent: true`；`sessions.json` 600 / 1 条 / 无口令明文；
  **`docker restart nas-admin` 后同一张 cookie 访问 `/api/overview` = 200**；
  登出后同一张 cookie = 401，会话表清空为 0 条。

### 注意
- 本次部署**换了 SECRET** → 之前发出去的旧 cookie 全部失效，用户需要**最后再输一次**口令；
  之后 30 天内不用再输（除非点「退出」或换浏览器/换访问地址）。
- 用 `127.0.0.1` 和 `192.168.1.100` 访问算**两个不同站点**，cookie 不共享——手机上固定用局域网地址即可。
- `env.nasadmin` 现在有 `NAS_ADMIN_PW` + `NAS_ADMIN_SECRET` 两行（600）；换口令只改前者。

## 2026-10-18 第三十八轮：文件页支持下载文件夹（打包 zip）

### 结论
用户要求「文件那一栏可以下载文件夹和文件」。原先只能下单个文件，文件夹点进去只能浏览。
现在：**每个文件行有「⬇️」、每个文件夹行有「⬇️打包」**，点文件夹即打包成 `<目录名>.zip` 下载。

- 后端新接口 `GET /api/fs/download_folder?path=`（走同一道登录门）：
  `zipfile` 递归打包到临时文件 → `FileWrapper` 流式返回 → **发完删**。
- 安全四道：**不跟随符号链接**（软链到 `/` 会把整盘打包出去）；**拒绝 FS 根**；
  **拒绝存储池顶层**（`vol1`/`data`/`var` 这类，等于整盘）；**总量上限默认 1GB / 20 万文件**
  （`NAS_ADMIN_ZIP_MAX_MB` / `NAS_ADMIN_ZIP_MAX_FILES` 可调），超限 413 并给人话提示。
- 单文件没权限 / 读失败 → **跳过该文件继续打包**，不让整包失败。

### 证据
- `test_admin.py` **110/0**（新增 19 条：zip 结构与内容一致、无绝对路径穿越、符号链接被跳过、
  非目录 400、根目录拒绝、FS 根拒绝、`vol1` 拒绝、具体项目可打包、未登录 401、
  超上限 413、单文件下载不受影响、**响应关闭后临时 zip 立刻清理**、启动扫陈旧包、不误删新包）
- `ui_admin.py` **51/0**（新增：每行都有下载按钮、文件夹按钮标「打包」、
  **真点下载 → 拿到 hello.txt**、**真点打包 → 拿到 .zip**、点下载不误触进入目录）
- 真机：打包 `作文批改/docs` → 200 / 167KB zip / **44 个文件 CRC 全通过**；
  打包 `blog` 目录经真实浏览器 → 下载到 `blog.zip`；`/host` 与 `/host/vol1` → 400 并给出人话原因；
  单文件 3152 字节正常；**/tmp 无残留**。

### 踩坑
1. **临时 zip 泄漏（真机发现 6 个残留）**：原来只用 `resp.call_on_close()` 删临时包，
   客户端中途断开/请求被打断时不触发 → `/tmp` 越攒越多。修法：改用
   `FileWrapper` 子类在 `close()` 里 `finally` 删 + `call_on_close` 双保险 +
   **启动时扫 1 小时前的陈旧包**（不误删新包）。
2. **打包整个盘根会把服务拖死**：容器里 FS_ROOT=`/host` 就是整机根，打包它要边扫边压 1GB，
   实测请求超时（curl 000）且写盘。修法：拒绝 FS 根 + 拒绝存储池顶层目录。
3. **测试里的假绿/假红两连**：
   ① 用 `rv.data` 读完不 `close()` 就断言"临时包没清理" → 假红（Flask test client 在响应
      未被关闭前确实不触发清理）；改成 `with rv: b"".join(rv.response)` 后 `rv.close()`。
   ② 直接断言"全局没有残留"会在前面**故意**用 `.data` 的用例后假红 → 改成只看**本次新增**。
4. **curl 探活超时不要用 20s**：打包 167KB 目录都可能慢，探活动手给 60s，否则误判成卡死。

### 不做的
- **不递归打包整个盘**（`/host`、`/host/vol1`）：这是保护性拒绝，不是缺陷。
- **不做断点续传/进度条**：打包在 1GB 上限内通常几十秒内完成，先不加。
