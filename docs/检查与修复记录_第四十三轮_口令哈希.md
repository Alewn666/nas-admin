# 检查与修复记录 · 第四十三轮：nas-admin 口令改存哈希（磁盘不落明文）

- 日期：2026-10-18
- 触发：用户「可以直接存储NAS上面那份密码的哈希值啊。这样子的话更安全。而且我还更方便使用。」
- 范围：nas-admin（NAS 8091 容器 + 云机 203.0.113.12:8080 systemd）
- 结论：**两台都改成存 PBKDF2-SHA256 哈希，明文口令从 env 文件里彻底消失；两台同用 NAS 那个口令，用户只需记一个。**

---

## 1. 用户要什么

原状：
- NAS `env.nasadmin`：`NAS_ADMIN_PW=<NAS口令明文>` + `NAS_ADMIN_SECRET`
- 云机 `/opt/nas-admin/env.nasadmin`：`NAS_ADMIN_PW=3UrkE4pAHHgXfrqucQy8HR`（22 位随机串，**明文落盘**）+ SECRET + FS_ROOT + NSENTER + DS_CFG

用户诉求两个：**更安全**（别把能直接登录的口令明文放盘上）+ **更方便**（不用另记一串随机口令）。

## 2. 方案

新增环境变量 **`NAS_ADMIN_PW_HASH`**，值形如：

```
sha256:<16字节盐的hex>.<32字节dk的hex>
```

- 算法：`hashlib.pbkdf2_hmac("sha256", 口令, 盐, 390000 轮, dklen=32)`
- 轮数可用 `NAS_ADMIN_PBKDF2_ROUNDS` 覆盖（**测试用低轮数跑得快，生产不动**）
- 比对走 `hmac.compare_digest`（定时安全）
- **用户登录仍敲明文**，服务端用同一盐现算哈希再比

优先级规则（有意设计）：**明文+哈希同配时以哈希为准**，误留的明文不生效。
格式坏了（盐非 hex / dk 非 hex / 前缀不对）→ **fail-closed，拒绝一切口令**，绝不因为「读不出来」而放行。

### 为什么不是「存 SHA256 口令本身」

单轮 SHA256 存口令等于没存：拿字典撞一遍秒破。必须带盐（防彩虹表/防两台撞同一个哈希）+ 高轮数（把单次校验拉到百毫秒级，GPU 批量撞的成本抬起来）。390000 轮取自 OWASP PBKDF2-HMAC-SHA256 建议量级。

## 3. 改了哪些文件

| 文件 | 改动 |
|---|---|
| `app.py` | +`import hashlib`；+`PASSWORD_HASH` / `_PBKDF2_ROUNDS` / `_pbkdf2()` / `hash_password()` / `_pw_ok()`；`configured()` 改 `bool(PASSWORD or PASSWORD_HASH)`；`login()` 的比对换成 `_pw_ok(pw)`；文档头与「未配置」文案同步 |
| `deploy.sh` | 首次部署接受 `NAS_ADMIN_PW_HASH=...`（与 `NAS_ADMIN_PW` 二选一），只写哈希时提示「无明文」 |
| `test_admin.py` | 新增 4 节（15~18）共 25 条断言 |
| `verify_hash_login.py` | **新增**：真机登录验收脚本，NAS/云通用 |

`PASSWORD` 原本只有 3 个用点（赋值 / `configured()` / `login()` 比对），改动面就这么大。

## 4. 验证（每条都有可重跑的命令）

### 后端套件
```
cd nas-admin && python3 test_admin.py        →  143 通过 / 0 失败
```
新增 4 节内容：
- **15. 口令哈希模式**：只配哈希 → `configured=True`；正确明文登录 200；错一个字符 401；**大小写错 401**；**多一个空格 401（不许 trim 宽容）**；前缀更长的错口令 401；未登录接口 401；`PASSWORD` 明文变量为空；**登录失败响应不泄露哈希值**
- **16. 同配优先级**：同配时正确口令（哈希那套）通过；**误留的明文口令不生效**
- **17. 格式异常 fail-closed**：salt 非 hex / 完全无前缀 / dk 非 hex 三种坏格式 → 一律拒绝一切口令
- **18. 可复现**：同口令两次生成哈希不同（随机盐）；**从哈希里取出盐重算得到同一个 dk**（证明比对路径不是碰运气）

**自证测试非空转**：把一条新断言故意改成恒假再跑 → 退出码 1、`142 通过 / 1 失败` ✘。测试确实会红。

## 5. 两台各用各的盐

NAS 与云机的哈希**不是同一个字符串**（各自独立随机盐）：
- NAS  盐前缀 `012bca938074ab1a…`
- 云机 盐前缀 `5b1cd96d1cca753b…`

这样做的额外好处：**给云机生成哈希时，明文一个字符都没经过网络**——在本机从 NAS env 管道读明文算出新哈希，只把哈希传上云。

## 9. 顺带订正一处文档错误

`scripts/ssh_cloud.sh` 注释里写的 scp 用法是错的：

```
# scp 模式：sh ssh_cloud.sh scp <本地文件> <远程路径>   ← 错
```

实际实现**把所有参数后缀成 `$USER_@$HOST:/tmp/`**，远程路径参数会被当成第二个本地文件去 stat 而报错。正确用法：`sh ssh_cloud.sh scp <本地文件>`（只传到 `/tmp/`，再 ssh 过去 `install` 到目标位置）。本轮就是这么用的。**注释没改**（不在本轮范围），下次动那个脚本时一并订正。
